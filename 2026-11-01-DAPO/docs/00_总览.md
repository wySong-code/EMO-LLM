# 00 总览：策略、对比与结论（一页纸）

> 目的：其它文档分别讲「为什么这么设计」「怎么跑的」「结果怎么读」，本文只回答三件事——**改了什么、跟谁比、结论是什么**。

## 一句话结论

在已跑完的 7B SFT 上接 DAPO（两臂各 300 周期），**训练时用的本地口径涨了 +0.0147，Kaggle 官方口径 −0.0078**；两臂差异仅 0.0004。

> ⚠️ **2026-11-05 勘误（第二轮）**：两臂 step50 已提交，榜分 **0.93580（legacy）/ 0.93345（score_focused）**，均高于 7B SFT 的 0.93243 —— 「官方口径全低于 SFT」只在本地验证集成立。legacy 排全项目第 2，但与榜首 3B GRPO（0.93638）只差 0.00058、与 7B GRPO step150 只差 0.00003，低于 0.002 可判阈值，**属并列而非超越**。本地 vs 榜分排序 ρ 由 +0.10（n=5）变为 **−0.107（n=7）**。
>
> ⚠️ **2026-11-02 勘误**：原写「最优提交仍是 SFT adapter」，该建议已被真实榜分否证（本地第一的 7B SFT 在榜上 0.93243 排第 6，本地垫底的 3B GRPO step50 是 0.93638 排第 1）。本地验证集不能用于选提交物，见 [06_结果分析 §7](06_结果分析.md) 与仓库根 `docs/03_审计与勘误记录.md`。

## 1. 实验设置

| 项 | 内容 |
|---|---|
| 起点 | `2026-10-30_23-00-Omni7B-SFT-GRPO/sft_run/adapter_best`（LoRA，源自 checkpoint-1638） |
| 方法 | DAPO：Clip-Higher(ε_low 0.2 / ε_high 0.28)、Dynamic Sampling(filter_groups)、Token-level Loss、Overlong Reward Shaping |
| 数据 | 训练 3352（冲突 411 = 真实 143 + 合成 268）、验证 666（冲突 74，一致 592） |
| 预算 | 300 周期 / 臂，单周期最多 48 次生成，K=8 |
| 并行 | 2 臂：`dapo7b`、`dapo7b_legacy`，同时开跑 |
| 耗时 | 约 7h30m/臂，日志 0 条 error/traceback/nan |
| 评测 | 同一 `score_omni_modality.score()`、同一 666 条、同一 batch 配置 |

**为什么开两臂**：只改一个变量组合（奖励系数 + 决策优势），其余全同，这样才能把「DAPO 本身」和「奖励改动」分开。单跑一臂只能得到「某个整体」的分数。

## 2. 相对原 7B GRPO，策略上改了什么

| 环节 | 原 GRPO | 本次 DAPO 主臂 | 是否起作用 |
|---|---|---|---|
| 算法 | GRPO（对称裁剪、序列级 loss） | DAPO 四补丁 | Dynamic Sampling 生效；Clip-Higher / Overlong 未触发 |
| 奖励分项 | 0.35 / 0.10 / 0.10 / 0.45 | 0.35 / 0.025 / 0.025 / **0.60** | **无效**（对照臂差 0.0004） |
| 决策优势 | 无 | +0.5×标准化决策正确性 | **无效**（同上，两臂差 0.0004） |
| 组选择 | 固定 1 冲突 + 1 一致各 8 次 | 最多 4 冲突 + 2 一致，优先决策有分歧组 | 部分生效（零更新 80%→53%） |
| 防误报 | KL | KL β=0.02 + 一致样本 SFT 锚 0.05 | 不足以抵消阈值下移 |
| 选点 | 单次验证总分 | 每 50 周期本地口径 + 情绪 F1 护栏 0.01 | **选点口径选错**（见 §4） |

## 3. 结果

### 3.1 三代方法（各自最佳点，同一 666 条）

| 方法 | local（0.3×召回） | 官方（0.3×准确率） | 情绪 F1 | 冲突召回 | TP/FP/FN |
|---|---|---|---|---|---|
| 7B SFT（基线） | 0.905166 | **0.940752** | 0.946144 | 0.8108 | 60/33/14 |
| 7B GRPO step150 | 0.909925 | 0.939655 | 0.950931 | 0.8243 | 61/38/13 |
| 7B DAPO step200 | **0.919887** | 0.932950 | 0.955314 | 0.8649 | 64/51/10 |
| 7B DAPO step50（官方最佳） | 0.905124 | 0.937556 | 0.950788 | 0.8108 | 60/40/14 |
| 7B DAPO-legacy step300 | 0.918155 | 0.932570 | 0.949824 | 0.8649 | 64/48/9 |
| 7B DAPO-legacy step50 | 0.905526 | 0.937508 | 0.952269 | 0.8108 | 60/41/14 |

**DAPO vs GRPO 取决于口径，且方向相反**：训练口径 DAPO 高 0.0100，官方口径低 0.0021。两个都低于 SFT。

### 3.2 两臂对照（隔离奖励改动）

| | dapo7b（0.60 + bonus 0.5） | dapo7b_legacy（0.45 + bonus 0） | 差 |
|---|---|---|---|
| 官方最佳 | 0.937556 | 0.937508 | 0.00005 |
| 官方 @local最佳点 | 0.932950 | 0.932570 | 0.00038 |
| FP | 51 | 48 | +3 |

两臂几乎重合 → **奖励重配被证伪**，无需再做单因素消融。

### 3.3 四项 DAPO 补丁

| 补丁 | 证据 | 判定 |
|---|---|---|
| Dynamic Sampling | 零更新步 240/300 → 160/300 | **生效**（唯一） |
| Clip-Higher | `clip_upper>0` 仅 8/300 步 | 未生效 |
| Token-level Loss | 全程启用 | 无法单独归因 |
| Overlong Shaping | `token_limit_hits=0` | 从未触发 |

## 4. 结论

1. **口径错位是本项目最大问题**：本地用 `0.3×冲突召回`（误报不罚），官方用 `0.3×冲突准确率`（误报扣分）。模型只需「多报警」就能让本地分上涨而官方分下跌。
2. **冲突判定阈值的变化**：TP 60→64，FP 33→51，每多抓 1 个真冲突对应 4.0～4.5 个假冲突（两臂、两套奖励配置一致）。
3. **官方口径最佳点**：DAPO 两臂都在 step50；`best.json` 按本地口径选的是 step200/300，选点需改用官方公式。
4. **训练集预筛**：3352 条只错 10 条（0.3%），88% 的采样组 8 候选全对。

## 6. 下一步（按性价比）

1. **P0 统一口径**：`local_score_present` 改成 `0.5×F1 + 0.3×conflict_accuracy + 0.2×spec`，重算 3B / 7B 全部历史对比与选点。
2. **P0 修 decision 奖励的冗余**：decision 项要么删掉，要么只保留标签位不能推导的部分。
3. **P1 补数据而非加步数**：按真实冲突子集（25 条）与跨模态矛盾样本构造难例，先让预筛 hard 数从 10 涨起来。
4. **不做**：加步数、加倍采样、换 PPO/DPO——问题不在优化器，也不在预算。
