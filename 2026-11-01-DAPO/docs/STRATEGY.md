# 7B 多模态情感任务的 DAPO 适配设计

## 1. 已观察到的问题

原 7B Combined SFT 在 666 条验证集的本地代理分为 0.9052（情绪 Macro-F1 0.9461；冲突 60/74；一致误报 33/592）。接续的普通 GRPO 跑 300 个周期：600 个 prompt 组里 540 个组八个回答全部满分，只有 60 组存在奖励差；仅 9 组的 `is_conflict` 决策发生分歧。验证集最佳 step150 为 0.9099，仅比 SFT 多命中一条**合成**冲突，真实冲突仍为 14/25，误报增至 38。结论是原训练在多数 prompt 上无法得到相对优势，且可学变化更多发生在情绪而不是冲突决策。数据见旧实验 `grpo_run/pilot_01/rollouts.jsonl` 和 `docs/03_结果分析.md`。

本实验的主要目标是提升**单位生成预算中的有效决策组数量**，同时观察真实冲突召回是否提高，并避免一致误报继续增加。不能用训练组有效率代替验证分数。

## 2. DAPO 论文与本实现的边界

[DAPO 论文](https://arxiv.org/abs/2503.14476)提出非对称裁剪、过滤无有效优势的动态采样、token 级损失聚合和超长回答的奖励塑形，原实验对象是长推理数学题。这里实现了前三项的任务化版本：

1. **非对称裁剪**：`clip_low=0.20`、`clip_high=0.28`，在 PPO surrogate 上分别约束负向与正向变化，并记录实际触发次数。若实际从未触发，不把它写成提分原因。
2. **预算受控动态补采**：一个采样周期最多尝试 4 个冲突 prompt 组、2 个一致 prompt 组，组内 8 个回答。只有有奖励差的组进入反向；若见到 `is_conflict` 决策分歧，优先保留该组并停止该桶补采；否则保留第一组辅助字段有差的组。未命中时记录并跳过，不会无限重抽。
3. **token 级聚合**：将所有有效回答的逐 token policy loss 与 KL loss 求和后除以有效回答总 token 数。旧脚本是每条回答先取均值再求平均；固定短 JSON 里二者差别预计小，保留为 DAPO 对照的完整实现。
4. **超长塑形不适用**：旧模型输出约 26 token，截断命中为零。保留原有严格 JSON 解析与非法格式 `−0.20` 奖励；不虚构长 CoT 信号。本方案应表述为**任务适配的 DAPO**，不是论文实验的逐项复现。

## 3. 任务适配的新增设计

### 3.1 双来源、双类别难度池

只在 **3352 条训练样本**上跑一遍 SFT greedy 预筛，逐条与训练金标比较，把四字段任一错误的样本加入初始难度池。验证集只在评测时调用，不进入训练池或难度更新。原始冲突与合成冲突分池；冲突抽样时原始来源目标概率 0.8。每桶优先从难度池取样的概率为 0.75，并照顾较少曝光的样本。这两个概率是**首轮实验设置**，未被证明最优。

每一次在线 rollout 反馈都会刷新难度池：`decision_active`（决策有差）、`auxiliary_active`（只有其他字段有差）、`all_same_not_perfect` 都进入难池。只有少数难题时，难池抽样概率按 `难题数/16` 自动下调，避免一条题被重复刷数百次；难池达到至少 16 条后才使用设定的 0.75 概率。普通抽样始终保留覆盖。与一次性离线预筛相比，在线刷新可跟上训练中模型行为变化；与纯在线无限补采相比，尝试次数有硬上限。

### 3.2 决策分歧优先，但不丢情绪信号

一个桶可以出现多组有效回答。优先选择决策有分歧的组，因为旧 7B 的 600 组里只有 9 组能直接教 `is_conflict`。若所有尝试都没有决策分歧，仍保留第一个情绪/模态字段有差的组，避免完全丢弃融合情绪信号。最终每周期最多接受 1 个冲突组与 1 个一致组；未接受的组只做诊断，不做旧/参考 logprob 或反向，节省后半段训练计算。

### 3.3 一致样本监督锚

旧 7B 训练里一致样本组仅 1/300 有奖励差。即使增加补采次数，也难保证每周期能得到一致组优势。若只在冲突组更新，模型可能更爱报 `yes`，使 0.2 的一致校准项下降。因此每个有 RL 更新的周期，取本周期一条**训练集一致样本**的完整四字段金标，加入系数 0.05 的 SFT 交叉熵锚。它只约束同一个 LoRA，且与 RL 共用已验证的视频/音频输入。锚权重也是待消融超参；它提高计算量，不保证压住误报。已有 reference KL (`β=0.02`) 继续限制策略漂移。

### 3.4 面向比赛分数的奖励配置

本节为可运行方案；逐步发现过程、旧模型与新方案的证据来源及消融判据见 [得分差异复盘与奖励重设计](04_得分差异复盘与奖励重设计.md)。

当前 7B SFT 验证集为 0.9052，旧 GRPO 最好为 0.9099；Kaggle public 的 7B SFT、GRPO step50、step150 分别为 0.93243、0.93444、0.93577。3B 的 GRPO step50 为 0.93638。7B 的验证集领先并未完整转化为 public 领先，说明不能只按单个本地峰值选策略。public 只覆盖测试集的一部分，且没有逐条标签，不能从 0.001–0.002 的差距断定模型真实排序；也不能把所有小于 0.02 的本地差异统称噪声。

四字段里 `pred_emotion` 和 `is_conflict` 进入官方打分；两路分支情绪只提供训练时的辅助监督。新默认 `score_focused` 奖励分配为**融合情绪 0.35、画面 0.025、文字/音频 0.025、冲突判断 0.60**，合计 1.00。旧 `legacy` 为 0.35/0.10/0.10/0.45，可用同一代码切换，作为奖励消融对照。两种配置都保留输出内在矛盾 −0.05、非法 JSON −0.20。提高冲突决策份额是待检验的假设，不是已经证实的提分手段；减少分支监督可能损伤融合情绪和跨模态泛化。

**只改奖励系数通常不够。** 若同一题的 8 个回答只有决策字段变化，GRPO 的组内标准化会抵消这一系数的整体放大；若 8 个答案决策完全相同，更不会凭权重造出决策梯度。旧 7B 的 600 组中只有 9 组有决策分歧。因而新默认在有决策分歧的组额外加入 `0.5 × 标准化决策正确性`，再和原总奖励优势相加；没有决策分歧时该项严格为 0。冲突组仍将合成优势乘 1.5，一致组为 1.0。这样提高的是**实际决策梯度**，不只是纸面奖励占比；数值 0.5 是实验超参，必须与 0 的对照比较。

比赛总分是 `0.5×Macro-F1 + 0.3×冲突召回 + 0.2×一致特异度`。固定每周期接受一条冲突和一条一致时，冲突优势乘 1.5 与 0.3/0.2 的类权重比例对应；动态过滤后两个桶的**有效组数可能不相等**，这个比值不再精确等于官方贡献。提升冲突召回也可能增加一致误报。每 50 周期同时记录三个分项、真实冲突命中和误报，以本地总分和情绪 F1 护栏选点，最终仍须独立 public/private 验证。

按当前验证集分母计算，多命中 1 条冲突带来约 `0.3/74=0.00405`，多误报 1 条一致损失约 `0.2/592=0.000338`。这解释了为什么适度提高冲突召回值得尝试，但**不等于一律报 yes**：连续多报 50 条一致会损失约 0.0169，足以抵消约 4 条冲突命中的收益。Macro-F1 也可能随策略漂移而下降。

## 4. 每周期执行顺序

```text
SFT adapter → 验证集基线 → 训练集 greedy 预筛
每周期：
  冲突桶：最多 4 次 × 每次 8 个候选
  一致桶：最多 2 次 × 每次 8 个候选
  每桶选择 1 个有效组（决策分歧优先）
  对选中回答计算 policy-old/reference logprob
  组内标准化总奖励 + 有决策分歧时的决策优势 → DAPO 非对称裁剪 + token 总量归一
  加一致样本 SFT 锚 → 2 次 PPO epoch 更新
  写入所有尝试、是否接纳、奖励差、更新次数与裁剪次数
每 50 周期：666 条全量 greedy 验证并保存 adapter
```

单周期最多 **48 次生成**，相对原 GRPO 的 16 次有明确 3 倍数量上限；实际可能更少。预筛另需 3352 次 greedy 推理。`--steps 300` 指采样周期而不是保证 300 次有效更新；如果一个周期两桶都无奖励差，该周期会安全跳过更新。实验的墙钟、有效率必须实测。

## 5. 成功标准与消融

核心指标：本地代理分 `0.5×pred_emotion Macro-F1 + 0.3×冲突召回 + 0.2×一致特异度`；分别报告 74 条冲突中的 25 条原始、49 条合成；还要报告误报 592 条分母。`best.json` 以总分并受情绪 F1 最多下降 0.01 的护栏选择，初始最佳点是原 7B SFT。由于仅有 25 条真实冲突，单次多对一两条不足以证明泛化；如资源允许，应多个种子和配对 bootstrap 对比。

建议按序对照（每组使用**独立输出目录**；若算力有限，至少保留第 1 与第 3 组）：

1. 旧 7B SFT：0.9052；旧 GRPO：step150 0.9099。
2. DAPO + 原奖励：`DAPO_RUN_TAG=dapo7b_legacy DAPO_REWARD_PROFILE=legacy DAPO_DECISION_BONUS=0 bash scripts/run_dapo.sh`。
3. DAPO + 决策奖励 0.60、决策优势 0.5：默认 `bash scripts/run_dapo.sh`。只将第 2、3 组的差异归因于这一**组合**，不可分别归因。
4. 若第 3 组胜出，再单独跑 `score_focused` + bonus 0 和 `legacy` + bonus 0.5，拆开奖励比例与决策优势各自贡献。

以上是**实验设计**。**2026-11-01 已按第 1、2、3 组执行完毕**（第 1 组为基线，第 2、3 组各跑 300 周期），结果见 [06_结果分析](06_结果分析.md)，时间线见 [05_训练记录](05_训练记录.md)。

实测结论（提前给出，避免继续按“待验证”理解本文）：

- 第 2、3 组的分差仅 **0.0004**（官方口径 0.932570 vs 0.932950），远小于方法间的差异；故第 4 组的单因素消融**前提不成立、不再执行**。
- 有效更新确实变多了：零更新步从 GRPO 的 240/300（80%）降到 160/300（53%），每步平均更新次数 0.2 → 0.93；同期训练口径升、官方口径降（见上表）。
- 本地代理分升、官方口径分降，说明**成功标准本身选错了口径**：`0.3×冲突召回` 不罚误报，官方用 `0.3×冲突准确率`。该项须先改。

所有臂保持了同一数据、种子、采样预算与评测链路。在这份已被 SFT 背完的数据上，DAPO 两臂的改动集中在放宽冲突判定阈值上；下一步可补真实困难数据或改输入证据。
