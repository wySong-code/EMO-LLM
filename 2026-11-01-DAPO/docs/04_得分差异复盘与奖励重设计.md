# 7B 得分差异复盘与 DAPO 奖励重设计

本文记录这次策略修改的**发现过程、证据、推导、代码对应关系与验证办法**。已发生的实验结果与尚未运行的新假设分别标明，避免把设计写成成果。

## 1. 起点：7B 在本地领先，public 优势却很小

比赛采用 `0.5 × pred_emotion Macro-F1 + 0.3 × 真冲突上 is_uncertain=yes 的比例 + 0.2 × 真一致上 is_uncertain=no 的比例`。本项目本地验证代码的 `local_score_present` 按这三个分项计算。提交脚本把四字段模型的 `is_conflict` 映射到提交字段 `is_uncertain`，把 `pred_emotion` 原样提交；画面和第二模态的分支标签只在训练时提供辅助监督。

| 模型 | 本地 666 条代理分 | Kaggle public |
|---|---:|---:|
| 3B SFT | 0.8840 | 0.93049 |
| 3B GRPO step50 | 0.8934 | 0.93638 |
| 7B SFT | 0.9052 | 0.93243 |
| 7B GRPO step150 | 0.9099 | 0.93577 |

本地值可从项目实验指标文件核对；上表 public 值来自本次讨论提供的 Kaggle 提交记录，并非由测试标签重算。public 测试样本的逐条真值未公开，不能把 public 的模型差距拆到具体错题或分项。

7B SFT 相比 3B SFT 的本地差约 `+0.0212`，由情绪 F1 的约 `+0.0029`、多命中 3/74 条冲突的 `+0.0122`、少误报 18/592 条一致的 `+0.0061` 构成；到 public 只剩 `+0.00194`。这说明验证集的优势没有稳定地按同样幅度出现在 public；**不能据此认定 7B 更差，也不能认定两者统计打平**。两套样本的难度、冲突构成和模型错误相关性未知，public 上 0.001–0.002 的差距没有逐条标签可做配对检验。

另一个重要修正：两套分数均为 public 高于本地，本地到 public 的提升幅度因模型而异，不能把本地差额直接外推。

## 2. 从旧 7B GRPO 的原始 rollout 找训练瓶颈

旧 7B GRPO 的 `grpo_run/pilot_01/rollouts.jsonl` 有 600 个 prompt 组，每组 8 个候选：

| 组状态 | 数量 | 对训练的含义 |
|---|---:|---|
| 8 个回答全对、同为满分 | 540 | 总奖励方差为零，组内优势为零 |
| 总奖励有差 | 60 | 能产生常规 GRPO 优势 |
| 冲突决策有分歧 | 9 | 才有直接比较 `is_conflict=yes/no` 的候选 |

旧 7B SFT 验证指标为总分 `0.905166`、情绪 F1 `0.946144`、冲突召回 `60/74`、一致正确 `559/592`。GRPO step150 为 `0.909925`、情绪 F1 `0.950931`、冲突召回 `61/74`、一致正确 `554/592`。step300 情绪 F1 继续到 `0.953825`，冲突召回回到 `60/74`、一致正确降到 `551/592`，总分降至 `0.906304`。这些变化说明继续训练并未稳定换来冲突召回，误报却逐步增加；不能只凭情绪 F1 或训练步数选择检查点。

对同一 prompt，GRPO 通常将总奖励标准化：`A_i=(R_i-mean(R))/(std(R)+epsilon)`。若八个答案奖励相同，`A_i=0`。更隐蔽的是：若它们**只**在冲突判断上不同，且 `R_i=c+w_decision×d_i`，提高 `w_decision` 后，分子和标准差会一起放大，标准化优势近似不变。因此把决策奖励从 0.45 改到 0.60，主要影响**多个奖励分项同时变化**的组；它本身不会让零方差组学会冲突判断。这是本次不能只改一个系数的核心原因。

## 3. 从比赛分数推导训练重点，同时保留代价意识

在这 666 条验证集上，真冲突 74 条、一致 592 条。在情绪预测不变时，多命中一条真冲突约增加 `0.3/74=0.00405`；多误报一条一致约损失 `0.2/592=0.000338`。局部兑换约 12:1，因此追求更高的冲突召回有合理空间。

但“多报 yes”不是无条件有利：多 50 个一致误报约损失 `0.0169`，相当于约 4.2 个额外冲突命中；情绪 F1 还可能变化。这个计算仅针对**当前验证集分母和情绪不变的近似**，不能直接用于未知的 public/private 分布。新策略必须同时监控冲突命中、误报和 Macro-F1。

## 4. 已落实到代码的设计

| 环节 | 原实现 / 对照 | 新默认配置 | 解决的问题 |
|---|---|---|---|
| 奖励分项 | 融合 0.35、画面 0.10、第二模态 0.10、冲突 0.45 | 0.35 / 0.025 / 0.025 / **0.60** | 将部分辅助字段权重转给提交所需的冲突判断，仍保留分支监督 |
| 决策优势 | 仅标准化总奖励 | 若 8 个候选的决策正确性有差，再加 `0.5 × 标准化决策正确性` | 避免只改系数后被组内标准化抵消；在实际有分歧的组增加决策梯度 |
| 组选择 | 原 GRPO 固定 1 冲突 + 1 一致，各生成 8 次 | 每周期最多试 4 个冲突组、2 个一致组，优先保留决策有分歧的组 | 把有限的更新预算放到有决策信号的训练题上 |
| 来源选择 | 原始冲突目标概率 0.67 | 0.80，并保留合成冲突 | 减少已接近饱和的合成冲突占用；这是待验证超参 |
| 防止误报 | KL 约束 | KL β=0.02 + 一致训练样本 SFT 锚 0.05 | 缓解只更新冲突组时的 yes 漂移；不能保证校准不下降 |
| 模型选择 | 看单次验证总分 | 每 50 周期看同一条本地评分链路，情绪 F1 不得较 SFT 基线下降超过 0.01 | 避免为冲突召回牺牲过多情绪表现 |

奖励代码在 `code/reward.py` 的 `REWARD_PROFILES`、`score` 和 `advantages`；训练器在 `code/train_dapo.py` 中通过 `--reward-profile` 与 `--decision-advantage-bonus` 读取和记录配置。`scripts/run_dapo.sh` 默认使用 `score_focused` + bonus 0.5；`DAPO_RUN_TAG` 隔离实验目录。`scripts/run_submission.sh` 使用相同标签读取对应最佳检查点。默认方案沿用已有 DAPO 的限额动态补采、非对称裁剪与 token 级聚合，未声称这些环节单独带来提分。

冲突组的标准化优势继续乘 1.5，一致组乘 1.0。这个比例与官方 0.3/0.2 的**类权重比**一致；它不是官方逐样本贡献的精确翻版。动态补采后两类进入更新的组数可能不同，实际训练权重还受组内方差、回答长度和候选数影响。

## 5. 如何判断这个改动是否真的有效

先在相同 7B SFT adapter、同一数据划分、同一随机种子与同一采样预算下做两组：

```bash
# 原奖励对照，写入独立目录
DAPO_RUN_TAG=dapo7b_legacy DAPO_REWARD_PROFILE=legacy DAPO_DECISION_BONUS=0 bash scripts/run_dapo.sh

# 得分导向方案
bash scripts/run_dapo.sh
```

这两组同时改变“奖励系数”和“决策优势”，结果只能评价**组合方案**。若组合有效，再做 `score_focused + bonus 0` 与 `legacy + bonus 0.5` 两个单因素消融。

> **实测结果（2026-11-01 已完成）：组合无效——两臂官方口径分差仅 0.0004，故单因素消融不再执行。** 详见第 6 节。每个实验单独记录启动配置、总生成量、有效组及决策有差组数、实际优化器更新数、每 50 周期验证三个分项、真实/合成冲突命中、592 条一致误报和墙钟。选择检查点时只用验证集，最终 public/private 表现单独报告。

优先回答三个问题：① 决策有差组是否显著多于旧实验的 `9/600`？② 相比旧 7B SFT `0.9052` 和旧 GRPO step150 `0.9099`，同一验证集总分是否提高？③ 若冲突召回增加，误报和情绪 F1 的代价是多少？零方差组变少只是机制诊断，不能代替最终分数。若有效决策组仍稀少，继续提高奖励比例不会解决候选缺少分歧的问题，应先考虑候选多样性或真实困难数据。

## 6. 已验证与实际结果

**训练前**（2026-11-01 上午）：离线完成 Python 编译、5 个单元测试，以及新旧配置各自的全量数据与抽样隔离检查；详细命令见 `VALIDATION.md`。

**训练后**（2026-11-01 14:07 启动 → 21:42 结束，两臂各 300 周期，四道门禁全部通过，日志 0 条 error/traceback/nan）。第 5 节留的三个问题现在有答案了：

| 第 5 节的问题 | 答案 |
|---|---|
| ① 决策有差组是否显著多于旧实验的 9/600？ | **没有实质增加**。两臂每步有效组仅 0.50 / 0.49，88% 的组仍是 8 候选全对（旧 GRPO 90%） |
| ② 相比 SFT 0.9052、GRPO step150 0.9099，总分是否提高？ | **只有本地口径提高**（0.9199 / 0.9182）；**官方口径反而下降**（0.9330 / 0.9326 vs SFT 0.9408、GRPO 0.9397） |
| ③ 冲突召回增加的代价是多少？ | 召回 0.8108 → 0.8649（+4 TP），代价是 FP 33 → 51/48（**+18 / +15**）、一致特异度 −0.030 / −0.025 |

结论：**0.60 奖励系数 + 0.5 决策优势这组改动没有产生可用的增益**。两臂官方分差仅 0.0004，比方法间差异小一个量级，所以第 5 节设想的第 4 组单因素消融**前提不成立，不必再跑**——问题不在系数怎么配，而在 decision 项与两个标签位在数据上 100% 自洽（734 条零例外），奖励里给它的 0.45~0.60 权重本质是重复计分。

因此这两组不能作为"取得成绩"写入报告。可写的只有负结果结论：**奖励重配无法改变「放宽冲突阈值」这一唯一学习方向**。完整数据见 [06_结果分析](06_结果分析.md)。
