# DAPO 结果分析（7B SFT → 预算受控 DAPO）

## 结论先说

**这次 DAPO 按训练时用的口径是 +0.0147，按 Kaggle 官方口径是 −0.0078。方向相反，且 12 个评测点无一例外低于 SFT 基线。**

本次运行可直接核对的价值在于：把「口径错位」从推测变成了可复算的证据。

> ⚠️ **2026-11-05 勘误（第二轮）**：上一条判断里的「低于 SFT 基线」只在**本地 666 条验证集**上成立。两臂 step50 实际提交后，榜分 **0.93580 / 0.93345**，**都高于** 7B SFT 的 0.93243 —— 本地口径对 DAPO 的判决在榜上被推翻。同时本地名次与榜上名次的 Spearman ρ 由 +0.10（n=5）退到 **−0.107（n=7）**。
>
> ⚠️ **2026-11-02 勘误**：本节早期版本写「最优提交仍是 SFT 基线」。该结论已被真实 Kaggle 榜分否证——本地第一的 7B SFT 在 public 只有 0.93243，本地垫底的 3B GRPO step50 是 0.93638（榜首）。**本地验证集不能用于决定提交物**，详见下方 §7（已重写）。

## 1. 两个口径的差异在哪里

评测代码里 `local_score_present` 的定义：

```
0.5×情绪宏F1(pred_emotion) + 0.3×冲突召回(conflict_recall) + 0.2×一致特异度(aligned_specificity)
```

Kaggle 官方公式（`score()` 里同一段权重）：

```
0.5×情绪宏F1(pred_emotion) + 0.3×冲突识别准确率(conflict_accuracy) + 0.2×一致特异度(aligned_specificity)
```

差别只有一个字：**召回（recall）还是准确率（accuracy）**。

- `recall = TP/(TP+FN)` —— 只看「真的冲突有没有被抓到」，**误报不扣分**
- `accuracy = (TP+TN)/N` —— 误报直接算错

当模型倾向于「多报冲突」时，这两个指标**必然反向移动**。这次就是。

## 2. 结果对照

| | SFT 基线 | dapo7b@200 | Δ | dapo7b_legacy@300 | Δ |
|---|---|---|---|---|---|
| **local_score**（训练口径） | 0.905166 | **0.919887** | **+0.014721** | **0.918155** | **+0.012989** |
| **kaggle_score**（官方口径） | **0.940752** | 0.932950 | **−0.007802** | 0.932570 | **−0.008182** |
| 情绪宏 F1 | 0.946144 | 0.955314 | +0.009170 | 0.949824 | +0.003680 |
| 冲突召回 | 0.810811 | 0.864865 | +0.054054 | 0.864865 | +0.054054 |
| 冲突准确率 | 0.929429 | 0.908408 | −0.021021 | 0.912913 | −0.016516 |
| 一致特异度 | 0.944257 | 0.913851 | −0.030406 | 0.918919 | −0.025338 |
| 冲突 F1 | 0.718563 | 0.677249 | −0.041314 | 0.688172 | −0.030391 |
| TP / FP / FN / TN | 60/33/14/559 | 64/51/10/541 | +4/**+18**/−4/−18 | 64/48/9/544 | +4/**+15**/−5/−15 |
| 全字段正确条数 | 599 | 586 | −13 | 588 | −11 |

> 注：`conflict_f1` 的定义是 `2·TP / (2·TP + FP + FN + invalid_positive)`，分母含「把冲突判成无效值」的样本。若只用 TP/FP/FN 手算会漏掉这一项——legacy@300 手算得 0.6919，实际 0.6882（多了 1 条 invalid）。**一切以 `step_*_metrics.json` 的字段为准，不要手算替代。**

两行加权分可以逐项拆开验算，确认差异全部来自冲突项：

```
Δlocal  = 0.5×0.009170 + 0.3×(+0.054054) + 0.2×(−0.030406) = +0.014720  ✓
Δkaggle = 0.5×0.009170 + 0.3×(−0.021021) + 0.2×(−0.030406) = −0.007802  ✓
```

情绪 F1 的 +0.0092 是真实增益，两套口径都认；**分歧全在 0.3 权重那一项**。

## 3. 机制：模型学到的是「把报警阈值往下推」

看混淆矩阵的移动方向，两臂完全一致：

- TP 60 → 64，FN 14 → 10 / 9：**多抓了 4 个真冲突**
- FP 33 → 51 / 48：**多报了 18 / 15 个假冲突**
- TN 559 → 541 / 544：一致样本被误判

每多抓 1 个 TP，代价是 4.0～4.5 个 FP。这个兑换比在 recall 口径下是赚的（0.3 权重下净 +0.0162），在 accuracy 口径下是亏的（净 −0.0063）。

**为什么梯度会朝这个方向走**：奖励函数 `score_focused` 里 decision 项占 0.60、标签位各占 0.35，而 `is_conflict` 位与两个标签位在数据里 100% 自洽（734 条零例外），4 个字段实际只有 2 个自由度。决策位是导出量，模型只要把两个标签位判得稍微「更爱报负面/更爱报冲突」，decision 位就跟着翻转，拿满 decision 奖励。**奖励没有对「一致样本上误报」施加与 TP 同等的权重**，于是净收益为正，训练就一路往这个方向推。

这不是 DAPO 的问题，是奖励设计与评测口径不同源的问题。

## 4. DAPO 四项补丁：只有一项真正生效

| 补丁 | 证据 | 判定 |
|---|---|---|
| Clip-Higher（ε_high=0.28） | `clip_upper>0` 仅 8/300 步 | **未生效**。梯度幅度太小，token 概率比从未顶到上界 |
| Dynamic Sampling（filter_groups） | 全对组被全部过滤；零更新步 240/300 → 160/300 | **生效**，是四项里唯一有实质作用的 |
| Token-level Loss | 全程启用 | 无法单独归因 |
| Overlong Reward Shaping | `token_limit_hits=0` | **从未触发**，本任务答案恒为 26 token |

动态采样确实把「有梯度的步数」从 20% 提到 47%，但它解决的是**零梯度**，而本次的瓶颈是**梯度指向错误**。让更多步有梯度，等于把错误方向推得更彻底——这解释了为什么 FP 的涨幅（+18）反而比 7B GRPO 时期（+8）更大。

## 4.1 两臂对照：奖励重配被证伪

两个臂的唯一差别是奖励配置（`score_focused` + 决策优势 0.5 vs `legacy` 原系数 + 决策优势 0），起手、数据、种子、预算、评测链路完全相同：

| | dapo7b（决策权重 0.60 + bonus 0.5） | dapo7b_legacy（原 0.45 + bonus 0） | 差 |
|---|---|---|---|
| 官方口径最佳点 | 0.937556（step50） | 0.937508（step50） | 0.00005 |
| 官方口径 @ 各自 local 最佳点 | 0.932950（step200） | 0.932570（step300） | 0.00038 |
| 冲突召回 | 0.8649 | 0.8649 | 0 |
| FP（一致样本误报） | 51 | 48 | +3 |
| 零更新步 | 160/300 | 165/300 | 5 |

**两臂几乎完全重合。** 把 decision 权重从 0.45 提到 0.60、再叠加 0.5 决策优势，没有改变任何一个评测点的走向，差异比方法本身低一个量级。

这说明「调奖励权重」这条路可以先排除了：decision 位是标签位的导出量，加权只是把同一个信号重复计分。原计划的两组单因素消融（`score_focused+bonus0`、`legacy+bonus0.5`）**前提不成立，不必再跑**。

## 6. 为什么「没有可学的」

启动时的 3352 条训练集 greedy 预筛给出了最硬的证据：

```
train_screen_summary.json
{"n": 3352, "hard": 10, "errors": {"emotion": 6, "decision": 4}}
```

**3352 条里只有 10 条做错（0.3%）**。策略文档原本设想「离线预筛分难度池」，结果难度池里几乎没东西。这也解释了 `cycles.jsonl` 里 88% 的组 8 个候选全对——不是采样策略的问题，是数据已经被 SFT 背完了。

在这个前提下，DAPO 的动态采样只能从 12% 的非全对组里捞，每步剩 0.5 个有效组，梯度方向由极少数样本决定，噪声极大但方向一致（都指向放宽判定）。

## 7. 提交建议（2026-11-02 修订：原建议已被真实榜分否证）

**原建议是「提交用 SFT adapter」，依据是本地 666 条验证集的官方口径分。这个建议是错的。**

把 7 个真正提交过的模型按两种口径排名：

| 提交物 | 本地官方口径（666 条） | 真实 Kaggle public（734 条） |
|---|---|---|
| 7B SFT | 0.940752（**本地第 1**） | 0.93243（榜上第 6） |
| 7B GRPO step150 | 0.939655（本地第 2） | 0.93577（榜上第 3） |
| 7B GRPO step50 | 0.939122（本地第 3） | 0.93444（榜上第 4） |
| 7B DAPO step50 | 0.937556（本地第 4） | 0.93345（榜上第 5） |
| 7B DAPO-legacy step50 | 0.937508（本地第 5） | 0.93580（**榜上第 2**） |
| 3B GRPO step50 | 0.928091（本地第 6） | **0.93638（榜上第 1）** |
| 3B SFT | 0.922292（**本地垫底**） | 0.93049（榜上第 7） |

Spearman ρ = **−0.107**（n=7，Σd²=62）。本地第一的 7B SFT 在榜上第 6；本地在 7B 内部垫底的 DAPO-legacy 在榜上第 2，只比榜首低 0.00058。**7B 五个点的本地名次与榜上名次近乎完全反转。**

**机制**：同一份 7B SFT 权重，在验证集上判冲突 93/666 = 14.0%（真冲突 11.1%），在测试集上判冲突 130/734 = 17.7%。测试集冲突先验明显更高，于是「多报冲突换召回」在测试集上赚、在验证集上亏。本地验证集不只是样本更少，**正类比例也不同**。

这条机制不能简单外推成「冲突报得越多榜分越高」：本次两臂的报冲突率是全场最高（19.6% / 19.2%），榜分却没有同步占顶——DAPO（19.6%）0.93345 既低于 legacy（19.2%）0.93580，也低于只报 17.2% 的 3B GRPO。冲突位改判会连带改动情绪位（两臂分别改 4 / 7 条），两项相互抵消，**单看报冲突率解释不了榜分**。

**因此本节的正确结论是**：

1. **不能用本地验证集决定提交物**。7 个点上本地名次与榜上名次的 Spearman ρ 从 +0.10（n=5）变为 −0.11（n=7）：不是弱相关，而是**没有关系、甚至反向**。
2. 榜分证据支持 **3B GRPO step50（0.93638）** 居首，**DAPO-legacy step50（0.93580）** 与 **7B GRPO step150（0.93577）** 紧随；三者两两相差 ≤0.00061，低于本项目 0.002 的可判阈值，**应视为并列而非排序**。
3. **DAPO 两臂的榜分都高于 7B SFT**（legacy +0.00337、score_focused +0.00102），与本文依据本地官方口径得出的「12 个评测点无一高于 SFT」方向相反。其中只有 legacy 的 +0.0034 略过 0.002 阈值，score_focused 的 +0.0010 不可判，**不宜写成「DAPO 显著优于 SFT」**。
4. 表内 DAPO 各点的**相对排序仍然有效**（同一集合、同一口径、同一链路），但绝对值不可外推到榜单。

臂内选点建议不变：**两臂都是 step50 官方口径最佳**（`best.json` 按训练口径选的 step200/300，恰好是官方分最低的区域）。选点逻辑与提交口径不同源，这一点必须先修。

| 选项 | 本地官方口径 | 说明 |
|---|---|---|
| DAPO step50 | 0.937556 | 臂内最佳，若要展示 DAPO 选它 |
| DAPO-legacy step50 | 0.937508 | 次选（与上者差 0.00005） |
| DAPO-legacy step200 | 0.935833 | 不推荐 |
| DAPO step200（`best.json` 选中） | 0.932950 | 不推荐——训练口径选点，官方分最低区 |
| DAPO-legacy step300（`best.json` 选中） | 0.932570 | 不推荐，同上 |

## 8. 下一步（按性价比排序）

1. **P0｜统一口径**：把 `local_score_present` 改成 `0.5×F1 + 0.3×conflict_accuracy + 0.2×spec`，重算此前所有实验（3B GRPO、7B GRPO、7B SFT）的选点与对比结论。在此之前，任何「本地涨了」的结论都不可信。
2. **P0｜改奖励的对称性**：decision 项要么删掉（与标签位完全冗余），要么对「一致样本上的误报」施加与 TP 同等的惩罚，否则误报得不到惩罚。
3. **P1｜数据层面定生死**：预筛只剩 10 条 hard，RL 没有原料。要么针对性构造难例（真实冲突子集、跨模态矛盾样本），要么承认「7B SFT 已到天花板」，把精力转向 3B 或其他方向。
4. **不做**：不加步数（300 步内已平台）、不堆采样数（K 加倍只是把同样的组重复算）、不换对齐算法（问题不在优化器）。

## 9. 局限

- 验证集仅 666 条，其中冲突 74 条。TP 变化 4 条就是 5.4pp 的召回波动，**单点比较的统计功效很弱**；本文没有做配对 bootstrap，结论依赖「方向一致 + 12 个点无例外」这个模式证据，而不是单点显著性。
- 每臂只跑了一次，无种子重复。
- 734 条测试集未提交，Kaggle 实际分数未验证；本文的 `kaggle_score` 是在 666 条验证集上按官方权重公式重算的，与榜单绝对值不可直接比较 **（官方看的是 734 条，非公开的 220 条无法验证，只能依赖公开榜单）**，但同一集合上的**相对**变化是可比的。
- `token_limit_hits=0` 说明答案长度恒定，Overlong Reward Shaping 在本任务上无法被检验。
