## 2. 对另一份分析的判断

**成立的方向：**奖励饱和与大批零方差组确实意味着上一轮训练效率低；一致样本 297/300 组全对的汇总提示 1:1 混采过多；验证集原始冲突只有 11/25 命中，而生成冲突 47/49 命中，资源应优先向原始冲突移动。

**不能直接接受的推论：**

1. **“把所有全对组丢弃就省掉 79% 生成算力”不成立。**必须先生成候选并打分才能知道全对；丢弃只能省后续策略/参考 logprob、反传。要省生成，应先减少每题候选数或提前识别容易题。
2. **“8 改 4，active 还能到 700 组”没有依据。**组变小通常降低观察到奖励分歧的概率；温度调高也可能只增加无效 JSON 或随机情绪错误。新代码采用先 4 个，仅当 4 个全同但未满分时再追加 4 个高温候选，实际 active 率要由新日志测。
3. **“原始冲突奖励乘 2.5、合成乘 0.2”若发生在组内标准化之前，几乎被完全抵消。**对同一组奖励 `R` 统一乘正数 `c`，`(cR-c均值)/(c标准差)` 与原优势相同。真正有效的是改变 prompt 出现频率，或在标准化**之后**缩放优势。
4. **不能由独立二项分布标准误断定 +0.0094“不显著”。**两个模型预测的是同一批 666 条样本，应看逐样本配对差异；再考虑从六个检查点挑最好会带来的选择偏差。当前缺上一轮逐条预测，无法补做可靠的配对区间。
5. **“换 PPO/DPO 一定没用”过于绝对。**稀少的奖励分歧会影响各种方法，但 critic、离线难例偏好对等会改变可用信号。此轮继续 GRPO 是为了先检验更直接、成本较低的采样和目标改动。

## 3. 数据与训练目标

原始课程标签保留。完整 train 3352、val 666；训练冲突 411，其中**原始 143**、**合成 268**，一致 2941。原始冲突按 VT 107 / VA 36 分布。`views.M1.label` 是画面情绪，`M2.label` 是文字或音频情绪，`M12.label` 是融合情绪；`sample_type` 等于 M1、M2 标签是否不同。训练只读取 train 的标签，val 仅用于固定评估和选 checkpoint。测试标签未参与。

GRPO 输出沿用课程基线 SFT 的四字段 JSON：`vision_emotion`、`text_emotion` 或 `audio_emotion`、`is_conflict`、`pred_emotion`。提交时再将 `is_conflict` 映射为 `is_uncertain`。没有把澄清问题放入本轮奖励。

## 4. 新方案：先解决样本覆盖，再解决奖励信号

### 4.1 按 100 次尝试固定配额

每 100 个 prompt：原始冲突 **75**、合成冲突 **5**、一致 **20**，整块随机洗牌。原始冲突采用洗牌后的无放回轮转，**前 200 次尝试必覆盖全部 143 条**；不会像上一轮随机抽样只覆盖部分原始冲突。若旧方案对 143 条做约 207 次有放回抽样，理论期望只覆盖 `143×[1−(142/143)^207]≈109` 条，与记录中的 114 条接近。一致样本以探索为主；若曾在训练 rollout 中出现错误 `is_conflict=yes`，将其加入训练集内 hard-aligned 池，之后有 25% 的一致抽样机会从该池选。这不使用验证标签挑训练样本。

75/5/20 是待检验的**起始假设**，不是由 600 组汇总精确推导出的最优比例。合成冲突保持少量曝光，避免彻底遗忘；一致样本保持 20%，并用验证集特异度护栏限制误报。若同一环境实测特异度跌出护栏，应首先增加一致比例，而非事后改测试预测。

**泛化风险：**训练原始冲突只有 143 条，而上一轮验证原始冲突仅 11/25 命中；若新日志显示训练决策已经接近满分、验证原始冲突仍不涨，说明主要瓶颈是训练到验证的分布差异。继续重复这 143 条可能过拟合，届时应转向输入证据与数据增强实验，不能继续单纯提高采样频率。

### 4.2 有界自适应候选数

每题先在温度 **1.25**、top-p **0.95** 下生成 4 个候选：

- 已出现不同奖励：立刻按这 4 个候选做 GRPO。
- 4 个全满分：记录并跳过 logprob 与反传，不再生成；可能错过第 5～8 个候选才出现的分歧，这是一项明确的成本取舍。
- 4 个全同但未满分：追加 4 个温度 **1.45** 的候选，给难题一次产生组内差异的机会；若 8 个仍全同，记录零方差，不伪造优势。

旧方案 600 组固定 8 个候选，共 4800 次生成。新方案若运行 600 次尝试，生成量在 **2400～4800** 之间，实际由 `summary.json` 记录；不能事先宣称 active 占比或最终耗时。

### 4.3 决策相关优势优先

基础奖励保持原来的 **0.35 融合情绪 + 0.10 画面 + 0.10 第二模态 + 0.45 冲突决策**。严格 JSON 错误记 −0.20；`is_conflict` 与输出两路情绪自相矛盾扣 0.05。这两个处罚是格式与逻辑护栏，上一轮是否产生梯度需新日志确认，**不把名义权重当成实际梯度份额**。

优势只在**同一输入**的候选内计算：`A=(R−本组均值)/(本组标准差+1e-6)`。如果候选的冲突决策正确性有分歧，标准化后的优势乘 **1.5**；若只有融合情绪等非决策字段有分歧，乘 **0.5**。这样针对上一轮“active 组多为融合情绪变化”的观察，控制更新真正作用于冲突任务的相对强度。若决策一直相同，单纯改变 0.45 权重或重复奖励冲突项，都无法凭空制造决策差异。

### 4.4 更新、参考约束与选模

使用原 SFT adapter 初始化 policy，同时加载**冻结的同一 SFT adapter**作为 reference。每个 active 组做 2 次 PPO 裁剪更新：lr `2e-6`、clip `0.2`、KL 系数 `0.02`、AdamW、梯度范数上限 1；旧策略与参考策略的 token logprob 都真实计算，没有离线 KL 常数替代。候选答案逐条生成、逐条反传，以控制显存。

默认最多 600 次 prompt 尝试，每 100 次在固定 666 条验证集贪心评测。checkpoint 必须同时满足：融合情绪 Macro-F1 ≥ 当次 SFT 基线 −0.01，且一致特异度 ≥ 基线 −0.01；在满足护栏的点中取总分最高。连续 3 次评估没有刷新最佳则早停。记录的是**尝试次数**、**active 组数**和**实际优化器步数**，避免把零梯度尝试算成有效更新。

## 5. 结果应如何判断

不要用“yes 率升高”或“active 率升高”单独宣布成功。至少同时看：

| 检查 | 目的 |
|---|---|
| 原始冲突召回、生成冲突召回、VT/VA 召回 | 确认收益来自需要解决的原始冲突，且无协议退化 |
| 一致误报与特异度 | 防止以大量误报换冲突召回 |
| 融合情绪 Macro-F1 | 防止 GRPO 学坏 SFT 强项 |
| active 组中 `decision_varies` 比例 | 判断新优势缩放是否真的作用在冲突决策 |
| JSON 有效率、零方差两类、实际生成数 | 检查高温探索是否引入噪声及成本 |
| 同口径 SFT 基线、所有 checkpoint | 防止只报被挑中的最好点 |

`paired_eval.py` 接受同一轮保存的 `sft_baseline_predictions.jsonl` 与任意 `attempt_XXXX_predictions.jsonl`，按冲突/一致分层做配对 bootstrap，输出总分差及诊断区间。**它不能消除同一验证集挑最优 checkpoint 的选择偏差**，因此区间只作内部诊断。若要对外声称稳定提分，需独立测试集或预先锁定 checkpoint 后复测。

## 7. 环境、运行命令与验收

课程基线记录的环境是 torch `2.4.0+cu124`、transformers `4.57.6`、peft `0.17.1`；项目没有 `requirements.txt` / 容器锁定文件。脚本对 transformers 和 peft **精确检查版本**；其他依赖包括 accelerate、av、numpy、soundfile、imageio-ffmpeg、Pillow、safetensors。`--allow-version-mismatch` 只用于有意尝试其他版本，不能视作兼容性验证。

新脚本支持两份模型同设备，也支持分设备（policy `cuda:0`、reference `cuda:1`）。所有路径默认相对于本目录自动定位；若基座不在 `../base_model`，需指定 `--base`。

```bash
cd /path/to/MM-Emotion-Combined-SFT-20261026/2026-10-29_23-22-GRPO
python -m unittest -v test_core.py
python train_grpo.py --check-data
python train_grpo.py --check-env

# 示例；CUDA_VISIBLE_DEVICES 按自己的设备编号填写
CUDA_VISIBLE_DEVICES=0,1 python train_grpo.py \
  --base /path/to/Qwen2.5-Omni-3B \
  --smoke-test --out runs/smoke_01

# 只有 smoke_test.json 明确 passed=true 后，再以新目录启动训练
CUDA_VISIBLE_DEVICES=0,1 python train_grpo.py \
  --base /path/to/Qwen2.5-Omni-3B \
  --out runs/pilot_01

# 完成后，按逐条预测做配对诊断
python paired_eval.py runs/pilot_01/sft_baseline_predictions.jsonl \
  runs/pilot_01/attempt_0100_predictions.jsonl
```

每个 `--out` 必须是**不存在的新目录**；烟测中会加载 policy 与 reference、各执行 VT 和 VA 的真实生成与反传、核对视觉/语言/音频 LoRA 梯度、并用一对构造的合法/错误答案真实跑一次 PPO 裁剪更新；它不会保存这次测试更新。完整训练时会保存每次评测指标、预测、adapter、采样日志、`best.json` 和 `summary.json`。
