## 四、数字从哪来

`docs/` 里**没有任何手抄数字**：除 01/02/03 三篇结论性文档外，06/07 与 xlsx 的所有表格都由 `_audit/` 下的脚本从本地原始文件生成。

| 数据块 | 源文件 | 生成脚本 | 产物 |
|---|---|---|---|
| 逐检查点指标 | 各 run 的 `*_metrics.json` | `build_master_table.py` | `master_results.csv`（35 行） |
| 评测曲线 | 同上 | `build_all_curves.py` | `curves_checkpoints_all.csv`（37 行） |
| 奖励侧逐步 | `rollouts.jsonl` | `build_reward_curves.py` | `curves_reward_per_step.csv`（2,100 行） |
| 优化侧逐步 | `sft_train.log` + PPO `rollouts.jsonl` | `build_optimizer_curves.py` | `curves_optimizer_side.csv`（19,985 行） |
| 训练过程信号 | 训练日志 + `cycles.jsonl` | `build_all_curves.py` | `curves_train_signals.csv`（31,175 行） |
| 子集拆解 | `*_metrics.json` | `build_report_pack.py` | `report_metrics_by_subset.csv`（185 行） |
| 十分位阶段 | `rollouts.jsonl` | `build_appendix.py` | `report_stage_fine.csv`（70 行） |
| 完整性核查 | 归档文件树 + 原始清单 | `build_completeness.py` | `report_completeness.csv`（37 行） |
| 数据包 | 以上全部 CSV | `build_report_xlsx.py` | `汇报数据包.xlsx`（12 sheet） |
| 图 | 以上全部 CSV | `plot_curves.py` | `figures/*.png`（8 张） |

复现方式：在项目根执行

```bash
python _audit/build_all_curves.py && python _audit/build_reward_curves.py \
  && python _audit/build_optimizer_curves.py && python _audit/build_report_pack.py \
  && python _audit/build_appendix.py && python _audit/build_completeness.py \
  && python _audit/build_report_xlsx.py && python _audit/plot_curves.py
```

全部只读已归档文件，**不重跑评测**。

## 五、编号与命名规则

- `docs/` 编号 01–08 连续，前缀即阅读顺序，**不留空号**。新增文档接在 08 之后并更新本篇。
- 各实验目录内部另有自己的 `docs/`（策略 / 训练记录 / 结果分析），编号只在本实验内有效，与根 `docs/` 不通用。
- 文件名一律「编号_中文标题.md」；不使用日期作前缀（日期写在正文首行）。
- 表格里的 `—` 表示「不适用」或「未提交」，`n/a` 表示「无此数据」，二者不混用。

## 六、两条口径（读任何数字前必看）

| 口径 | 公式 | 用在哪 |
|---|---|---|
| **训练口径** `local_score` | 0.5×情绪宏F1 + **0.3×冲突召回** + 0.2×一致特异度 | 训练选点用这个 |
| **官方口径** `official_score` | 0.5×情绪宏F1 + **0.3×冲突准确率** + 0.2×一致特异度 | Kaggle 榜分用这个 |

两者**在多报冲突时必然反向**：本地涨、榜上掉的例子在本项目里出现了 2 次（见 `03_审计与勘误记录.md`）。任何「本地提升了」的结论，都先用官方口径重算一遍再写进材料。
