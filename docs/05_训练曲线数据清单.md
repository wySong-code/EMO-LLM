# 训练曲线数据清单（五轮实验）

本文件回答一个问题：**每个实验的训练曲线，到底有没有数据、有多少、缺什么。**

答案不是"Yes/No"，而是三层：

| 层 | 内容 | 是否完整 |
|---|---|---|
| ① 评测曲线 | 每个检查点在 666 条验证集上的分数与子指标 | **完整**，37 个检查点全覆盖 |
| ② 奖励侧训练曲线 | 每步/每 attempt 的候选奖励、组内方差、零梯度组比例 | **完整**，2100 个训练点全覆盖（可离线重算） |
| ③ 优化侧训练曲线 | loss / KL / entropy / 裁剪比例 / 梯度范数 | **只有 2/6 个实验有**，其余四个从未落盘 |

→ 所以"训练曲线"整体上是**不完整的**：能画的是"奖励怎么变"，画不出的是"梯度怎么走"。下面逐项列清。

## 2. 三层数据各自的位置与字段

### ① 评测曲线 → `_audit/curves_checkpoints_all.csv`（37 行）

由 `_audit/build_all_curves.py` 从各目录的 `*_metrics.json` 现场重算，含本地/官方双口径、五个子指标、混淆矩阵四格、`all_fields_correct`。

| 列 | 含义 |
|---|---|
| `local_score` | 0.5·情绪宏F1 + 0.3·冲突**召回** + 0.2·一致特异度（训练选点口径） |
| `official_score` | 0.5·情绪宏F1 + 0.3·冲突**准确率** + 0.2·一致特异度（Kaggle 口径） |
| `official_delta_vs_sft` | 相对**本实验** SFT 起点的官方口径增量 |
| `TP/FP/FN/TN` | 74 条真冲突上的混淆矩阵 |

> ⚠️ 历史遗留坑：`_audit/3b_step_curves.csv` 里那列叫 `kaggle_score`，但它**不是真实榜分**，是官方口径公式在验证集上的值。新表一律用 `official_score`，避免再被名字误导。

### ② 奖励侧 → `_audit/curves_reward_per_step.csv`（2100 行）

由 `_audit/build_reward_curves.py` 从各实验 `rollouts.jsonl` 的逐样本候选记录离线重算，**每个训练点一行**：

| 列 | 含义 |
|---|---|
| `groups` / `candidates` | 该步尝试了几组、共几个候选（GRPO 8 个/组，r2 4 个/组） |
| `mean_reward` / `std_reward` | 全部候选的奖励均值与标准差 |
| `within_group_std` | 组内标准差的均值 —— **GRPO 的 advantage 就是这个量**，为 0 则该组无梯度 |
| `zero_spread_group_rate` | 组内候选奖励完全相同（极差=0）的组占比 = 白跑比例 |
| `decision_acc` | 候选里 `is_conflict` 判对的比例 |
| `top_reward_share` | 组内最高奖励被多少候选命中（奖励饱和的另一视角） |
| `conflict_group_share` / `aligned_group_share` | 该步抽到的冲突/一致样本占比（采样是否漂移） |

这是本项目**此前完全没有**的一份数据。从它可以直接读出：

| 实验 | 平均奖励 | 零梯度组占比 |
|---|---|---|
| 3B GRPO r1 | 0.9666 | **81.2%** |
| 3B GRPO r2 | 0.9396 | 67.8% |
| 7B GRPO | 0.9884 | **90.0%** |
| 7B DAPO | 0.9814 | 87.9% |
| 7B DAPO-legacy | 0.9795 | 87.8% |
| 3B PPO | 0.9477 | n/a（PPO 是 4 个不同样本，非同一 prompt 的候选，组内方差无意义） |

上表是**逐步占比的均值**；若按总组数合并计算，数字相差不到 1.5 个百分点（如 r1 是 487/600 = 81.2%，DAPO 是 1536/1725 = 89.0%）。

7B 侧 9 成的组 8 个候选完全相同 → advantage 恒 0 → 该步更新为零。这就是"奖励饱和"的量化版本，比此前只看 `cycles.jsonl` 的零更新计数更直接。

> 注意：DAPO 两臂改过奖励权重，跨实验的 `mean_reward` **不可直接比较**，只在同一实验内部看趋势。

### ③ 优化侧 → `_audit/curves_optimizer_side.csv`（长表）

> 「来源」列的路径均**相对于该行的实验目录**（7B SFT → `2026-10-30_23-00-Omni7B-SFT-GRPO/`，3B PPO → `2026-10-30_13-39-PPO/`）。

| 实验 | 指标 | 点数 | 来源 |
|---|---|---|---|
| 7B SFT | `loss`、`gradient_norm`、`learning_rate`、`task_loss_{full,vision,text,audio}`、`grad_norm_{language,vision,audio}` | 1638 步 | `sft_run/train/train_metrics.jsonl` |
| 3B PPO | `policy_loss`、`value_loss`、`kl`、`clip_fraction`、`tokens`、`policy_grad_norm_sum`、`value_grad_norm_sum` | 300 attempt | `runs/pilot_01/rollouts.jsonl` 每行的 `update` 字段 |
| 3B GRPO r1 / r2、7B GRPO、7B DAPO 两臂 | **无** | 0 | — |

PPO 这批是本轮新发现的：`rollouts.jsonl` 每行除了 4 个样本明细，还带一个 `update` 字典（policy_loss / value_loss / kl / clip_fraction / 两个梯度范数数组），此前只用了 `PROGRESS` 行里每 10 attempt 一次的那份。实测范围：policy_loss −0.517 → −0.056，value_loss 0.136 → 0.0039，KL 0 → 0.014。

**为什么 GRPO 系没有**：`train_dapo.py:486-496` 确实算了 `policy_loss` / `kl` / `clip_grad_norm_`，但 498-503 行写入 `cycles.jsonl` 时只挑了组级字段（updates / groups / buckets / clip 计数），这三个标量随之被丢弃。3B 的 GRPO 脚本同理，只 `print` 了 STEP 行的计数。**没有备份、没有 wandb、没有 tensorboard**（已全库扫过，0 个 `events.out*` / `*.wandb`），所以不可能事后补。要补只能重训。

## 3. 缺口清单（按"能不能补"分类）

| 缺口 | 影响 | 能否补 |
|---|---|---|
| 4 个 GRPO/DAPO 实验的 loss / KL / entropy / grad_norm | 无法判断是否发散、无法看策略偏移速度 | **不能**，只能重训并改一行代码 |
| 3B GRPO r2、PPO 的组级统计只有每 10 attempt 一采 | 60 / 30 点，趋势够用但看不到单步抖动 | **能**，从 `rollouts.jsonl` 逐组重算（本文件 ② 已做） |
| 3B GRPO r1 / 7B GRPO 的 PPO 式 `update` 字段 | — | 本来就没有，结构不同 |
| 7B SFT 的 `task_loss_*` 个别步缺失（1574–1637 / 1638） | 曲线有少量断点 | 不补，缺失步就是当时该模态没参与该 batch |
| 检查点权重（DAPO 两臂各 1.6 GB 等） | 不影响曲线 | 未归档，需要时重跑导出 |

## 4. 复现

```bash
python _audit/build_all_curves.py        # ① 评测曲线 + 组级信号
python _audit/build_reward_curves.py     # ② 奖励侧逐步曲线
python _audit/build_optimizer_curves.py  # ③ 优化侧（只有 SFT / PPO 有行）
python _audit/plot_curves.py             # 由上面三份 CSV 出图（可选）

# 汇报用的结构化表与 Excel（在这三份之上再聚合）
python _audit/build_report_pack.py       # 子集明细 / 阶段聚合 / 实验矩阵
python _audit/build_appendix.py          # 分实验附录：十分位阶段明细 + 数据溯源表
python _audit/build_report_xlsx.py       # 打包成 docs/汇报数据包.xlsx
```

所有脚本都只读已归档文件，不重跑评测、不重算模型输出。图在 `docs/figures/`，共 8 张。

[`07_分实验数据附录.md`](07_分实验数据附录.md)（按实验：每 10% 一段的数、每个数的来源文件）、

## 5. 一句话结论

- **评测曲线**：五轮齐全，37 个点，两套口径，可直接比较。
- **奖励侧训练曲线**：五轮 RL 齐全，2100 个训练点，本轮首次算出来；7B 侧 9 成组无梯度是"奖励饱和"最硬的证据。
- **优化侧训练曲线**：只有 7B SFT（1638 步）和 3B PPO（300 步）有；GRPO 系四个实验的 loss/KL **从未存在过**，任何"loss 收敛/发散"的说法对它们都不成立。
