## 一、结论

把课程基线的 SFT 配方原样搬到 Qwen2.5-Omni-7B，再接第一轮 GRPO 的 step50 配方，三版 CSV 都出了（纯 SFT / GRPO 第 50 步 / GRPO 第 150 步）。核心结论三条：

1. **换 7B 的收益是真的，但范围很窄**：画面情绪 +0.035、一致特异度 +0.030、冲突 F1 +0.096，三项都通过配对 bootstrap（95% CI 不含 0）。而总量指标（情绪宏 F1、准确率、综合分）点估计为正但区间跨 0 —— **"7B 更能读懂画面、更少误报冲突"站得住，"7B 整体更好"还不能断言。**
2. **GRPO 在 7B 上几乎没有收益**：step50 综合分 −0.0003，全程峰值（step150）+0.0047，bootstrap 都不显著；3B 同口径 **+0.0097 且显著**。原因不是调参，是**奖励饱和** —— 300 步里 540/600 个候选组"8 个全对"、优势恒为 0，只有 60 步真的发生了梯度更新。
3. **剩下的误差主要在数据，不在模型**：25 条真实冲突样本上两个模型的综合情感都只对 20 条；而且这批样本的标注里 `pred_emotion` 有 60% 跟画面、40% 跟另一模态，**不存在"由两个模态推出综合情感"的固定规则**。

## 二、关键数字

**3B → 7B（同配方，唯一变量是模型；666 条验证集，同一评测链路）**

| 指标 | 3B SFT | 7B SFT | 差值 | 显著性 |
|---|---|---|---|---|
| 本地综合分 | 0.8840 | 0.9052 | +0.0212 | 不显著（P=0.913） |
| 情绪宏 F1 | 0.9403 | 0.9461 | +0.0058 | 不显著 |
| 情绪准确率 | 0.9429 | 0.9489 | +0.0060 | 不显著 |
| **画面情绪** | 0.9174 | 0.9520 | **+0.0346** | **显著** [+0.014, +0.054] |
| **一致特异度** | 0.9139 | 0.9443 | **+0.0304** | **显著** [+0.010, +0.056] |
| **冲突 F1** | 0.6264 | 0.7186 | **+0.0922** | **显著** [+0.024, +0.171] |
| 冲突召回 | 0.7703 | 0.8108 | +0.0405 | 不显著（分母仅 74） |

增益的形状不是"多判对几条"，而是**误警从 51 条降到 33 条**（TP 57→60、FN 17→14、准确率只涨 4 条）。真正有实质进步的只有：真实冲突识别 10/25 → 14/25。

**GRPO 的边际收益：随 SFT 质量单调递减**

|---|---|---|
| 3B + GRPO step50 | **+0.0097** [+0.0009, +0.0223] | **显著** |
| 7B + GRPO step50 | −0.0006 [−0.0126, +0.0121] | 无效 |
| 7B + GRPO step150（最高点） | +0.0048 | 不显著，且特异度已从 0.9443 掉到 0.9358 |

**奖励饱和的直接证据**

## 三、三个 CSV 与权重

| 产物 | 位置 | 说明 |
|---|---|---|
| CSV #1（纯 SFT） | `submissions/sft7b/submission.csv` | 734 行，解析 734/734，零回退；桌面副本 `submission_omni7b_sft.csv` |
| CSV #2（SFT + GRPO step50） | `submissions/grpo7b_step50/submission.csv` | 734 行，解析 734/734；桌面副本 `submission_omni7b_grpo_step50.csv` |
| **CSV #3（SFT + GRPO step150）** | `submissions/grpo7b_step150/submission.csv` | **验证集综合分最高的一版（0.9099）**；桌面副本 `submission_omni7b_grpo_step150.csv` |
| SFT 最优 LoRA | `sft_run/adapter_best/` | `checkpoint-1638`，综合分 0.9055 |
| GRPO step50 LoRA | `grpo_run/adapter_step50/` | CSV #2 所用（对齐 3B 口径） |
| GRPO step150 LoRA | `grpo_run/adapter_step150/` | 综合分最高（0.9099），CSV #3 所用 |

三版 CSV 的行集合完全相同（734 条，`sample_id` 一一对应），差异只在预测内容：

- SFT → step50：**9 行不同**（3 行改情绪、6 行只改 `is_uncertain`）
- step50 → step150：**21 行不同**
- SFT → step150：**23 行不同**（3.1%）

step150 的改动方向很集中：相对 step50，`is_uncertain=yes` 从 130 条升到 **140** 条、`conflict` 判定率 17.7%→**19.1%**、情绪 `positive` 从 288 升到 **299**（SFT 是 290）。这与验证集上"召回 0.8108→0.8243、特异度 0.9443→0.9358"的取舍一致，是同一个倾向在新数据上的复现。

另一个可查的内在校验：按"`conflict=no` 时综合情绪应等于画面情绪、`conflict=yes` 时应不等于"这条口径统计 734 条的自洽率，SFT 是 0.8992，step50 不变，step150 升到 **0.9114**。也就是说新增的 10 条冲突判定大多满足内部逻辑，不是随手乱报。

## 四、四条值得记住的判断

1. **视觉塔没有变大，但画面读得更准了。** 预检显示 3B 与 7B 的 vision / audio 可训练参数**完全相同**（12,462,080 / 11,796,480），只有语言塔不同。所以涨的不是"眼睛"，是**语言侧把视觉特征映射成标签的能力**。这个区分有用：继续堆语言侧参数仍有收益，换更大的视觉编码器是另一条未验证的路。反过来，音频那一路 7B 还略退（0.950→0.941）。
2. **GRPO 的失效是"奖励太容易"，不是"7B 不适合 RL"。** 同一套奖励，前 50 步平均奖励 3B 0.964（距满分 0.036）、有效候选组 18.8%；7B 0.987（只剩 0.013）、有效组 10.0% —— 余量只剩三分之一。挤出来的那点分还是用特异度换的（F1 单调升、特异度单调降），因为 F1 在奖励里权重最高（0.35）。
3. **选点准则本身在偏好"敢判冲突"。** SFT 第 3 轮胜出靠的是召回 0.784→0.811，而它第 2 轮的 F1 和特异度其实更高；GRPO 第 150 步胜出同理。0.3（召回）> 0.2（特异度）这个权重，决定了选点一直在挑更爱报警的检查点。
4. **评测 batch 确实不改变结论，但不是零差异。** 同一份权重，SFT 链路（batch 8）与 GRPO 链路（batch 4）各评一遍：666 条里 **1 条**预测不同，综合分 0.9055 vs 0.9052。所以跨模型比较统一取同一条链路，把这条 1/666 的噪声抵消掉。

## 五、局限

- 视觉塔未变，本轮不能推出"7B 全面优于 3B"。
- 冲突分母只有 74 条（真实 25 / 合成 49），召回相关结论区间很宽（±0.05~0.13）。
- 7B 与 3B 都是"各自独立挑最优检查点"，选择偏差未消除。
- GRPO 结论依赖选点：7B 峰值在第 150 步，CSV #2 按 3B 口径取第 50 步，**CSV #3 才是取峰值那一版**。两版并存，是为了让"口径对齐"和"分数最优"各自都有据可查。
- 标注只做了内部自洽性检查（666 条全自洽，0 条矛盾），未做语义级人工复审。

细节、证据文件与复现命令见 `docs/` 三份文档；所有数字可用 `python code/analyze_results.py` 从本地产物重算。
