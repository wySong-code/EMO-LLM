## 三、实际命令

### 3.1 SFT（`scripts/run_sft.sh`，micro-batch 4，eval-batch 8）

```bash
# 预检
python -u code/sft/train_omni_combined_sft.py \
  --mode pilot --model ../base_model --model-id Qwen/Qwen2.5-Omni-7B \
  --dataset sft_run/dataset_view --data sft_run/data_view --cache sft_run/media_cache \
  --output sft_run/preflight --micro-batch 4

# 正式训练
python -u code/sft/train_omni_combined_sft.py \
  --mode train --model ../base_model --model-id Qwen/Qwen2.5-Omni-7B \
  --dataset sft_run/dataset_view --data sft_run/data_view --cache sft_run/media_cache \
  --output sft_run/train --pilot sft_run/preflight \
  --epochs 3 --eval-batch 8 --micro-batch 4
```

### 3.2 GRPO（`scripts/run_grpo.sh`，配方与 3B 第一轮逐项相同）

```bash
python -u code/grpo/train_grpo.py \
  --base ../base_model \
  --adapter sft_run/train/checkpoints/checkpoint-1638 \
  --code code/sft \
  --dataset-root ../training_dataset/Dataset \
  --out grpo_run/pilot_01 --media-cache grpo_run/media_cache \
  --policy-device 0 --reference-device 1 \
  --steps 300 --candidates 8 --ppo-epochs 2 --lr 2e-6 --kl-beta 0.02 --clip-eps 0.2 \
  --temperature 1.1 --top-p 0.95 --max-new-tokens 128 \
  --original-conflict-prob 0.67 --conflict-advantage-scale 1.5 \
  --eval-every 50 --eval-batch-size 4 --f1-drop-guard 0.01 --seed 42
```

### 3.3 提交（`scripts/run_submit.sh`）

```bash
python -u code/make_submission.py --base ../base_model --adapter <adapter> \
  --test ./test_release.jsonl --out submissions/<name> \
  --batch-size 4 --max-new-tokens 192
```

三份 CSV 用的是同一个脚本、同一批超参（batch 4 / 192 token），**只有 `--adapter` 不同**：

| CSV | `--adapter` | `--out` |
|---|---|---|
| #1 | `sft_run/train/checkpoints/checkpoint-1638` | `submissions/sft7b` |
| #2 | `grpo_run/pilot_01/checkpoints/step_0050` | `submissions/grpo7b_step50` |
| #3 | `grpo_run/pilot_01/checkpoints/step_0150` | `submissions/grpo7b_step150` |

这保证了 CSV 之间的差异只能归因于权重，不能归因于预处理、prompt 或解析器。

### 3.4 串联队列（`scripts/chain_after_sft.sh`）

常驻进程轮询 SFT 状态 → 出 CSV #1 → 跑 GRPO → 出 CSV #2。日志：`logs/chain.log`。CSV #3 不在队列里，需要单独跑一次（18 分钟）。

## 八、偏差与处置（按发生顺序）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 探针四个 micro-batch 全 OOM | 探针未挂 LoRA，对冻结基座求梯度 → 整份权重都要梯度缓冲 | 探针先 `attach_lora()`；并把 train / generate 拆成两个进程（失败反传会留下半分配显存） |
| 2 | 预检报 `--data` 目录里找不到 `train_pool.jsonl` | 上游把 pool 放 `data/`、manifest 放 `manifests/`，而脚本要求同一目录 | 建 `sft_run/data_view/` 三个软链接合并，内容不动 |
| 3 | 预检报 `validate()` 路径断言失败 | 上游 `Dataset/videos` 是指向外部的软链接，`resolve()` 后落在 `--dataset` 之外 | 建 `sft_run/dataset_view/`：jsonl 软链 + `videos/` 用 `cp -al` 硬链接树（同 inode 不占空间） |

第 2、3 两条容易被误解成"改了数据"，实际只改了目录布局：训练读到的仍是同一份 3352/666 行（md5 已核对）与同一批视频文件（硬链接同 inode）。

## 十、复现步骤

```bash
# 1. 数据视图（一次性，不占空间）
bash scripts/run_sft.sh 4 8        # 内部自动建 data_view / dataset_view / 硬链接缓存

# 2. SFT（约 6 小时）
bash scripts/run_sft.sh 4 8

# 3. CSV #1（约 18 分钟）
NAME=sft7b bash scripts/run_submit.sh sft_run/train/checkpoints/checkpoint-1638

# 4. GRPO（约 3 小时）
bash scripts/run_grpo.sh

# 5. CSV #2（约 18 分钟）
NAME=grpo7b_step50 bash scripts/run_submit.sh grpo_run/pilot_01/checkpoints/step_0050

# 6. CSV #3：取验证集峰值那一步（约 18 分钟）
NAME=grpo7b_step150 bash scripts/run_submit.sh grpo_run/pilot_01/checkpoints/step_0150

# 7. 或者一条命令串起来（只跑到 CSV #2，CSV #3 需另行补跑）
bash scripts/chain_after_sft.sh
```

校验点：SFT 结束应得到 `total_optimizer_steps = 1638`；预检的 `trainable_parameters` 三段应为 `40,370,176 / 12,462,080 / 11,796,480`（后两段若与 3B 不同，说明加载错了模型）。
